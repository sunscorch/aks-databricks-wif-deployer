Phase 1: Obtain the Kubernetes projected tokenKubernetes projects a signed ServiceAccount JWT into the Pod before the application reads it.
Mount signed JWT containing iss, sub, aud, and exp
main() + required_env()Read DATABRICKS_OIDC_TOKEN_FILEPATH, then load the JWT with Path.read_text().
Phase 2: Inspect the JWT locallyThis is an early diagnostic check. It is not cryptographic signature verification.
inspect_projected_jwt()Split the JWT into three parts; call decode_jwt_part() for header and claims; verify expected audience, expected subject, and expiration.
Safe diagnostic outputPrint algorithm, key ID, issuer, audience, subject, expiry, and remaining lifetime. Never print the JWT value.
Phase 3: Exchange the tokenThe Databricks token endpoint performs the authoritative federation validation.
exchange_for_databricks_token()
POST /oidc/v1/token with Kubernetes JWT, Databricks client_id, token-exchange grant, JWT subject-token type, and scope=all-apis
Databricks federation validationResolve the AKS issuer metadata and public signing keys; verify the JWT signature; compare issuer, audience, and subject with the service principal federation policy.
Return a short-lived Databricks OAuth access token, token type, scope, and lifetime
TokenExchangeResultKeep access_token in memory and separate it from the printable token metadata summary.
Phase 4: Access Databricks resourcesThe same in-memory OAuth token is used for REST API checks and the SQL Warehouse connection.
test_workspace_apis() calls databricks_get() with Authorization: Bearer <access_token>
